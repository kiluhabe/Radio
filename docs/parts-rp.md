## ⚡ 受動部品

**追加の外付け部品は原則不要**。Pico 本体・各モジュール基板（M5807PA、SSD1306）はいずれも必要なデカップリングコンデンサと I²C プルアップを onboard で実装済み。

旧 Pro Mini 構成で「IC ごとに 200µF」が効いたのは、USB-シリアル LDO の貧弱さ＋ブレッドボードの接触不良が前提だったため。RP2040 ＋ ユニバーサル基板ハンダ実装ではどちらも構造的に解消するので、後付けデカップリングは見送って実装後に問題が出てから足せばよい。

万一あとから挙動が不安定で、特定モジュールに onboard 部品が無い個体に当たった場合のみ、当該 IC の VCC〜GND 直近に **100nF セラミック + 10µF セラミック**を追加する。

## 🔌 Pico ピン割り当て（暫定）

| Pico Pin # | 名称 | 接続先 | 用途 |
|---|---|---|---|
| 36 | 3V3 (OUT) | 3.3V レール | 全モジュールの VCC 供給 |
| 3, 8, 13, 18, 23, 28, 33, 38 | GND | GND レール | 共通 GND（複数本まとめて結線） |
| 6 | GP4 | I²C0 SDA | M5807PA (DATA) / SSD1306 (SDA) 共通バス |
| 7 | GP5 | I²C0 SCL | M5807PA (CLOCK) / SSD1306 (SCL) 共通バス |
| 4 | GP2 | Encoder A（ロータリーエンコーダ側） | 内部プルアップ、VCC不要 |
| 5 | GP3 | Encoder B（ロータリーエンコーダ側） | 内部プルアップ、VCC不要 |
| 9 | GP6 | Push switch（タクトスイッチ側、別体） | 内部プルアップ、VCC不要。COM→GND, NO→GP6 |
| 21 | GP16 | UART0 TX | デバッガ Pico の UART RX へ（`defmt` ログ、任意） |
| 22 | GP17 | UART0 RX | デバッガ Pico の UART TX へ（任意） |
| 裏面 SWD パッド | SWCLK / SWDIO | デバッガ Pico の SWD ピンへ | 書き込み・デバッグ |

I²C はデバイスが 2 つなので 1 バス共有で問題なし。VBUS（40番ピン）はアンプ撤去に伴い未使用（今後 5V 系が必要な部品を追加する場合の予備）。

## 🔋 電源方針

- **入力**：Pico の VBUS（USB 5V）
- **3.3V 系のみ**：Pico オンボードの 3.3V LDO（RT6150、約 1A 級）で全モジュールを駆動
  - M5807PA typ 30mA、SSD1306 typ 10mA、Pico 本体 30mA、エンコーダ 0mA → 合計 ~70mA、余裕十分
- アンプ撤去によりアクティブスピーカー側の電源は本機と分離（スピーカー自身の電源/電池で駆動）。5V 系配線は不要
- **デカップリング**：Pico・各モジュールとも onboard 実装済み。追加部品は不要

旧構成のような USB-シリアル LDO 経由の電源マージン問題は構造的に発生しない見込み。

## 🐞 デバッグ運用

### デバッガ Pico（Picoprobe）配線

| デバッガ Pico | ターゲット Pico | 信号 |
|---|---|---|
| GP2 | SWCLK（裏面パッド） | SWD クロック |
| GP3 | SWDIO（裏面パッド） | SWD データ |
| GND | GND | 共通 |
| GP4 | GP17 (UART0 RX) | デバッガ TX → ターゲット RX |
| GP5 | GP16 (UART0 TX) | デバッガ RX ← ターゲット TX |

### ホスト側ツール

- `probe-rs`（書き込み・RTT ログ・デバッグ統合）
- `cargo-embed` または `cargo run`（runner に `probe-rs run` を設定）
- `defmt` クレートで構造化ログ
