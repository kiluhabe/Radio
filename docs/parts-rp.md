## ⚡ 受動部品

基板・モジュール類は必要なデカップリングと I²C プルアップを onboard 実装済みなので、**原則として追加は不要**。ただし今回の構成では以下 4 点を必ず入れること。

⚠️ **本基板自体には I²C プルアップ抵抗を実装していない**。RP2040 の内部弱プルアップのみで動かしている。モジュール側のプルアップに依存した構成でマージンは薄いので、配線が長くなる場合や不安定なときは外付けプルアップ（2.2〜4.7kΩ 程度）の追加を検討すること。

## 🔌 ピン割り当て

RP2040-Zero のエッジピンは GPIO0〜15 / GPIO26〜29 の 20 本。**使用は 7 本**で余裕がある。

| GPIO | 用途 | 接続先 |
|---|---|---|
| GP26 | **I²C1 SDA** | M5807PA (DATA) / SSD1306 (SDA) 共通バス |
| GP27 | **I²C1 SCL** | M5807PA (CLOCK) / SSD1306 (SCL) 共通バス |
| GP12 | ロータリーエンコーダ A（天面ディスク） | 内部プルアップ、VCC 不要 |
| GP13 | ロータリーエンコーダ B（天面ディスク） | 内部プルアップ、VCC 不要 |
| GP11 | アクションボタン | 内部プルアップ |
| GP10 | 電源スイッチ（音量ポット内蔵） | 内部プルアップ。レベル検出（押しボタンではなく位置） |
| GP9 | ステータスLED（WS2812B） | PIO 駆動（`ws2812-pio` 等）。R1（330Ω）を介して DIN へ |
| ― | 3V3 | 全モジュールの VCC 供給 |
| ― | 5V (VSYS) | WS2812B（1N4148 経由で 4.3V） |
| ― | GND | 共通 GND |
| （GPIO16） | オンボード RGB LED | 外部に出ていない。内部インジケータとして利用可 |

⚠️ **GP26/GP27 は I²C1 の有効なペア**（I²C0 の固定ピンセットにこの組み合わせは無い）。

### リセットスイッチの配線

**RUN はどのパッド・ヘッダにも出ていない**（公式回路図で確認済み。P1=23 ピンは GPIO0〜15 / GPIO26〜29 / 3V3 / GND / VSYS、P2/P3=裏面パッドは GPIO17〜25 と GND）。

オンボード RESET ボタン（Key2）は **RUN と GND の間に直結**されているだけなので、**このボタンの両端にリード線をはんだ付けして `Reset Swtich` の 2 ピンコネクタへ引く**。外付けボタンがオンボードボタンと並列になる。プルアップ抵抗は不要（RP2040 内部にある）。上記の 100nF は必ず入れること。

## 🔋 電源方針

- **入力**：RP2040-Zero の USB Type-C
- **3.3V 系**：オンボードの **RT9013-33**（500mA クラス）で全モジュールを駆動
  - M5807PA typ 30mA、SSD1306 typ 10mA、本体 30mA → 合計 **約 70mA**、余裕十分
- **5V 系**：WS2812B のみ。**VSYS（5V ピン）は USB VBUS に直結**（Pico と違いショットキーダイオードが入っていない）。外部から 5V を入力する場合は USB 接続時の電源衝突に注意
- **デカップリング**：各モジュール onboard 実装済み。追加は上記「受動部品」の 4 点のみ

## 🐞 デバッグ運用

⚠️ **RP2040-Zero は SWD（SWCLK/SWDIO）を一切引き出していない**（公式回路図のネットリストで確認：両信号ともチップのピン以外に接続先が無い）。Pico 構成で使っていた **probe-rs によるデバッグ・`defmt` の RTT ログ・ブレークポイントは使えなくなる**。

| 項目 | Pico 構成（旧） | RP2040-Zero 構成（新） |
|---|---|---|
| 書き込み | SWD（`cargo run`）または UF2 | **UF2 のみ**（BOOTSEL 押しながら接続 → `elf2uf2-rs -d`） |
| ログ | `defmt` + RTT | **USB シリアル（CDC）または UART を GPIO に割り当てる** |
| ブレークポイント | 可 | **不可** |
| デバッガ Pico | 必要 | **不要** |

- デバッガ用の 2 枚目の Pico / Debug Probe は**不要**になる（購入済みなら他用途へ）
- ファームウェア側は `defmt-rtt` / `panic-probe` がログ経路として機能しなくなるため、USB シリアルまたは UART ベースの出力へ差し替えが必要
